# S3 · 建模迭代 —— GPT-2 科研全仿真

> 口径三段式
> - 目标：还原方法从 v0 到论文最终形态的迭代链，中间版本一个都不许跳。
> - 现状：上一阶段《档案 · S1》《档案 · S1.5》《档案 · S2》（方向定型：不做微调、不预设任务、任务描述来自自然文本；且 §2.3 三处架构改动无引用无动机）。
> - 限制：v0/v1 可以是【合理重构】，但每一版的死因必须让内行信服。**凡陈述"某个设计是为了解决某个问题"，必须引出论文里的动机原句，否则降级为待验猜想。**

## v0：把微调那一刀砍掉，其他原样不动

最直接的形式化：GPT-1 的流水线是「预训练 → 拍平成序列 → 加线性层 → 微调」。我把最后两步直接删掉，留下「预训练 → 拍平成序列 → 采样」。

具体做法是：把任务写成一段文本，喂进去，让模型接着写，从写出来的东西里取答案。比如问答就写"问题……答：____"，让模型续写。

**它为什么不够**——三个层次：

1. **接口层：答案取不出来。** 模型续写的是**网页文本的分布**，不是**答案的分布**。我问"谁是第一个被弹劾的总统"，它接着写"这个问题在历史上有很多讨论。安德鲁·约翰逊是第一位……"——答案在里面，但不在开头，我不知道该切哪一段。**注意这不是工程问题，是目标函数的问题**：语言建模只保证"整段文本的概率高"，从不保证"答案出现在某个固定位置"。这一条后来在 LAMBADA 上以最干净的形式复现：模型给出的**大多是句子的合法续写，但不是合法的最后一个词**【可查证：§3.3 原句 most predictions are valid continuations of the sentence, but are not valid final words】。它证明的不是模型不会，而是**模型没有被告知"这里要的是那个词"**。

2. **效率层：慢一个量级。** 论文 §2 留下了我自己写的预备实验结论：足够大的语言模型确实能做这种玩具式的多任务学习，**但远比显式监督慢**【可查证：§2 原文 learning is much slower than in explicitly supervised approaches】。慢意味着必须用规模和时间去换——这是全篇最终走向"四档 log-uniform 模型矩阵"的真正原因，也是合作者在 S1.5 里让步的代价。
   附带一句理论上的安慰：监督目标与无监督目标是同一条式子，只是 evaluand 是子集，所以无监督目标的全局最小点也是监督目标的全局最小点【可查证：§2 原文】。**这句话的用处是防线，不是进展**：它保证这条路"原则上能到"，但不保证"我们能到"。

3. **风险层：我拿什么证明它是"学"的？** 如果模型只是把训练语料里出现过的问答原样背出来，那我做出的东西叫**检索**，不叫零样本任务学习。这一层在 v0 阶段我甚至不知道怎么设计检验，但它像根刺一样留在计划里——**后来它变成了整整一节（§4 Generalization vs Memorization）。**

## v1：先救输入——表示层死了两回

v0 的接口问题我不打算用后处理硬解（S1.5 已经砍掉那条腿）。换个思路：**如果不改模型，能不能改"文本怎么进模型"？**

**第一条死路：字符 / 词级 BPE。** 参考的 BPE 实现是在 Unicode 码点上做的【可查证：§2.2 原文 reference BPE implementations often operate on Unicode code points and not byte sequences】。这意味着要覆盖全部 Unicode 字符串，基础词表就得超过 130,000【可查证：§2.2 原文 This would result in a base vocabulary of over 130,000 before any multi-symbol tokens are added】——而当时 BPE 任务上常用的词表是 32k 到 64k【可查证：§2.2 原文 the 32,000 to 64,000 token vocabularies often used with BPE】。**代价不是钱，是分配：词表是有限的，多出来的 7 万多个槽位本来可以装词。**

**第二条死路：直接上字节级 LM。** 字节这个粒度天然满足"任何 Unicode 字符串都能算概率"这个要求【可查证：§2.2 引用 Gillick et al. 2015 作为该思路的先例】。但字节级语言模型在 One Billion Word Benchmark 上打不过词级模型【可查证：§2.2 原文 current byte-level LMs are not competitive with word-level LMs】；**而且我自己在 WebText 上重跑，也看到了同样的差距**【可查证：§2.2 原句 We observed a similar performance gap in our own attempts to train standard byte-level LMs on WebText】。这一条是"文献说不行，我自己也验证了不行"。

**活下来的版本：字节级 BPE。**

它的定位是"字符级与词级之间的实用中间态"【可查证：§2.2 原文 a practical middle ground between character and word level】。三个具体决策：

- 基础词表 **256**（字节）而不是 13 万【可查证：§2.2 原文 only requires a base vocabulary of size 256】；
- **禁止跨字符类别合并**：直接把 BPE 用在字节序列上会产生次优合并，因为它是频率贪婪的启发式，结果会把 `dog`、`dog.`、`dog!`、`dog?` 各占一个槽位【可查证：§2.2 原文，含这四个具体形态】——"limited vocabulary slots and model capacity 的次优分配"【可查证：§2.2 原文 sub-optimal allocation of limited vocabulary slots and model capacity】；
- **对空格开一个例外**：这一条例外"显著提升压缩效率，同时只带来极小的词碎片化"【可查证：§2.2 原文 We add an exception for spaces which significantly improves the compression efficiency while adding only minimal fragmentation of words across multiple vocab tokens】——**这是全文少数给出"代价—收益"对比的一句话，所以它是动机可查证的**。

最终词表 50,257【可查证：§2.3 原文 The vocabulary is expanded to 50,257】。

**v1 暴露的新问题**：输入表示修好了，"答案在哪"的问题一点没动。v1 只让模型能把任何字符串读进来、算得出概率，**读得进来 ≠ 答得对**。

## v2：最后一块拼图不是架构，是"接口约定"

到这里我卡了很久。真正的转折不是某个模块，是**我放弃了"让模型自己知道要干什么"这个念头**。

McCann 他们那句"语言可以把任务、输入、输出都表示为符号序列"【可查证：§2 原文】在 S1 时被我读成"任务说明可以是训练数据的自然成分"。到 v2 我才意识到它的另一半用途：**它同时是推理时的接口约定**。既然任务是文本，那我就在推理时**把任务写进上下文**——不是改模型，是改我给它的那段文本。

论文里七处探针全部是这个约定的实例【可查证：以下逐句取自 §3】：

| 任务 | 接口约定（论文原句） |
|---|---|
| 阅读理解（CoQA） | 条件于文档、对话历史、以及最后一个 token `A:`【§3.5】 |
| 摘要（CNN/DM） | 在文章后加上 `TL;DR:`，再生成 100 个 token【§3.6】 |
| 翻译（WMT-14） | 上下文给若干 `english sentence = french sentence` 样例对，最后以 `english sentence =` 收尾【§3.7】 |
| 问答（Natural Questions） | 用问答样例对做种，帮助模型推断该数据集的短答风格【§3.8】 |

**这就是最后一块拼图：零样本 ≠ 零格式。** 模型不需要微调，但需要**接口**；接口不是新参数，是一段人写的自然文本。它把 v0 的"答案取不出来"降级成了"答案在哪一段"的工程细节——语义上仍然是零样本，因为模型没有为任何任务更新过权重。

**然后是架构侧的四刀。** §2.3 列出的改动是：

1. LayerNorm 移到每个子块的输入，类似 pre-activation 残差网络【可查证：§2.3 原文】；
2. 在最后一个自注意力块之后追加一个 LayerNorm【可查证：§2.3 原文】；
3. 一个新的初始化，把残差层权重按 1/√N 缩放，N 为残差层数【可查证：§2.3 原文】；
4. 上下文从 512 提到 1024，batch 从（GPT-1 的）更小值提到 512【可查证：§2.3 原文】。

**纪律自检（这一节必须扣死）：以上四条，论文全部只写"做了什么"，一句动机都没给，也没有任何引用。** 按 S3 的纪律，任何"某设计是为了解决某问题"的说法都必须引出论文原句——这里引不出来。所以这四刀在本阶段**一律降级为待验猜想**，标注如下：

| 改动 | 论文给出的动机句 | 本阶段判定 |
|---|---|---|
| LayerNorm 前移 | 无 | 待验猜想（深层网络训练稳定性的常见处方之一） |
| 末端追加 LayerNorm | 无 | 待验猜想 |
| 残差初始化按 1/√N 缩放 | 无 | 待验猜想（"account for the accumulation on the residual path with model depth"是描述、不是动机） |
| context 512→1024 / batch 512 | 无 | 待验猜想 |

**这几行是本轮与 GPT-1 首跑最大的一处方法论差异。** GPT-1 当年 S3 犯的错，是把 v1 的辅助目标动机写成"治小数据过拟合"——而论文 §3.2 的动机原句是"提升泛化并加速收敛"，Table 5 的逐任务差值更是反着的：**动机写错，整条迭代链就救错了人。** 那一轮的教训是"必须引出原句"；这一轮的处境更硬：**原句根本不存在**。所以这里没有可救的错，只有必须承认的不可知——四条架构改动的真实动机，任何仿真都只能重构，S8 必须把它们整批列入"编圆了但论文没这回事"的高危区。

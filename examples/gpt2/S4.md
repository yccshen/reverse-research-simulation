## 【数据轨】

### 1. 数据从哪来：四个候选，三个被否

| 候选 | 谁支持 | 否决理由（论文依据） |
|---|---|---|
| Common Crawl | 我（一作，理由：免费、近乎无限） | **两种否决叠加**：文献层面，Trinh & Le 2018 已公开抱怨其中大量文档"content are mostly unintelligible"，且他们的解法是"只保留与目标数据集最相似的文档"，这等于把任务知识预先注进语料；**作者层面，我们在自己的初始实验里观察到了同样的质量问题**【可查证：§2.1 原文两处】 |
| Wikipedia | 合作者（理由：干净、可控） | **被主动移除**，理由不是脏而是"干净得太大众"：它是许多数据集的共同来源，与测试任务重叠会让分析复杂化【可查证：§2.1 原句 We removed all Wikipedia documents from WebText since it is a common data source for other datasets and could complicate analysis due to overlapping training data with test evaluation tasks】 |
| 单域语料（新闻 / 小说 / 书籍） | 无 | 与核心 claim 直接冲突：我们要的恰恰是**域的多样性**，单域语料在定义上做不到 |
| Reddit 出站链接 | 合作者（S1.5 分歧一的收口） | ——**被采纳** |

**采纳方案的两句关键原文必须逐字记住**：
- 「只抓取经过人类策展/筛选的网页」，因为"人工筛选整份网页爬取会异常昂贵"【可查证：§2.1 原文】；
- 「抓取 Reddit 上至少获得 3 个 karma 的所有出站链接」，这可以看作"其他用户是否觉得这个链接有趣、有教育意义或只是好笑"的启发式指标【可查证：§2.1 原文】。

**"至少 3 个 karma"这个数字是整条数据轨的支点**：它用一个免费的、由人投票产生的代理信号，替换掉了"人工筛选"这个买不起的工序。它同时也是 §2.1 里我们与 Trinh & Le 划界线的物质基础——**他们的语料带任务偏好，我们的不带。**

抽取器：Dragnet 与 Newspaper 的组合【可查证：§2.1 原文】。

### 2. 清洗与筛选：三次返工（本阶段第一条负结果重点区）

**返工一：`<UNK>` 和分词痕迹反过来咬了我们。**
我们在 S3 赌的是"字节级输入 → 不需要任何有损预处理与分词"，这句话我们当时觉得很漂亮。**但下游数据集的另一个方向是脏的**：那些评测集大多经过激进的标准化，带着"断开标点与缩写、被打乱句子"这类分词痕迹【可查证：§3.1 原文 aggressively standardized text, tokenization artifacts such as disconnected punctuation and contractions, shuffled sentences】，甚至出现 `<UNK>` 这个字符串——而它在 WebText 里极端罕见，40 亿字节里只出现 26 次【可查证：§3.1 原文】。
**结果是我们要反向造工具。** 论文的解法是造"可逆的去分词器"，把尽可能多的预处理痕迹还原掉，并且特别强调它们**可逆**，所以数据集的对数概率仍然算得出来；论文把它定位为"一种简单的域适配"【可查证：§3.1 原文 invertible de-tokenizers ... can be thought of as a simple form of domain adaptation】。
**这条的教训很硬：我们为了"不引入分词偏差"而放弃分词，结果不得不为别人的分词偏差写一个逆向器。规避一个偏差，不消除它，只是换了个方向撞上去。**

**返工二：非英语滤不干净。**
按 S1.5 的决议，我们主动移除全部非英语网页【可查证：§3.7】。**然后语言检测器给出的答案是：WebText 里还剩 10MB 法语**【可查证：§3.7 原文 detected only 10MB of data in the French language】。
当时这是一条"过滤器没做干净"的坏消息，写进论文时它变成了一条证据（见 S5）。

**返工三：评测集自己也不干净。**
我们在做 CBT 的数据重叠分析时发现，测试集里的一本书——吉卜林的《丛林之书》——就在 WebText 里【可查证：§3.2 原文 Data overlap analysis showed one of the CBT test set books, The Jungle Book by Rudyard Kipling, is in WebText】。**处理方式是放弃测试集、改报验证集**【可查证：§3.2 原文 we report results on the validation set which has no significant overlap】。这条后来直接催生了 §4 整节——**我们知道"要查重叠"这件事，是《丛林之书》教的，不是反过来。**

### 3. 数据规模怎么定的

**坦白讲：不是算出来的，是过滤器的边界决定的。**

- 抓取始点是全部 Reddit 出站链接，规模是 **4500 万条链接**【可查证：§2.1 原文 these 45 million links】；
- 去重与启发式清洗之后，得到**略多于 800 万篇文档、总计 40GB 文本**【可查证：§2.1 原文 slightly over 8 million documents for a total of 40 GB of text】；
- 时间上切成 **2017 年 12 月之前的链接**，这一版被明确称作 WebText 的"初步版本"【可查证：§2.1 原文 a preliminary version of WebText which does not include links created after Dec 2017】。

**"40GB 不是上限，是这一次的余量"——这一点有两处独立内证：**
1. 论文 §3 说所有模型**都还在欠拟合 WebText**，给更多训练时间，留出集的困惑度仍在改善【可查证：§3 原文 All models still underfit WebText and held-out perplexity has as of yet improved given more training time】；
2. §4 用 Figure 4 展示训练集与测试集性能**一起随模型规模上升而改善**，并据此再次得出"即便 GPT-2 在很多方面仍在 WebText 上欠拟合"【可查证：§4 原文】。

**这两句是整篇论文在数据轨上的自白：规模没有到顶，是工期和算力到顶了。**

## 【实验轨】

### 4. 核心问题 → 倒推出需要哪几个实验

我要回答的核心问题有三个，每个都倒逼出一组实验：

| 核心问题 | 倒推出的实验 | 论文落点 |
|---|---|---|
| 容量是不是这件事的关键？ | 训练四档规模（近似对数均匀），在全部指标上铺出曲线 | §3 开头、Table 2、Figure 1（多任务）、Figure 2（CBT）、Figure 3（WSC）、Figure 4（WebText 自身） |
| 零样本到底能不能真做任务？ | 七个任务探针，每个都用该领域自己的指标 | §3.2 CBT、§3.3 LAMBADA、§3.4 WSC、§3.5 CoQA、§3.6 摘要、§3.7 翻译、§3.8 问答 |
| 这是任务学习还是记答案？ | 用 8-gram Bloom 过滤器量化重叠 | §4，Table 6 + Figure 5 |

**第三组实验是我在 S3 v0 就埋下的那根刺。** 它的设计细节值得记下来：Bloom 过滤器装 WebText 训练集的 8-gram，字符串先归一化为"只含小写字母数字词、单空格分隔"以提高召回；误报率上界压到 1e-8，并用 100 万个字符串做验证，**命中数为零**【可查证：§4 原文三处】。

### 5. baseline 选谁、最怕被谁比下去

**原则**：每个任务用它自己领域的既有最好结果，不另造统一 baseline。论文 Table 3 的 SOTA 行来自五个不同来源并逐列标注【可查证：Table 3 caption】。

**最怕的三处（按怕的程度排）**：
1. **One Billion Word Benchmark。** 这是我们主动认输的那一列——它是最大的数据集，而且它自己的预处理最有破坏性：句级打乱"移除了全部长程结构"【可查证：§3.1 原文 1BW's sentence level shuffling removes all long-range structure】。**我们模型的长处正好是长程依赖，这一列把我们的长处切掉了。**
2. **摘要。** 我们心里有数：定性上像模像样，定量上会很难看。
3. **翻译。** En→Fr 方向我们完全没底，因为语料里非英语是**被我们主动删掉的**。这一列的预期本来是"随便报个数、承认不行"。

### 6. 超参数怎么定的

**只有一句可查证的交代**：每个模型的学习率是人工调的，目标是在 WebText 的 5% 留出样本上取得最好的困惑度【可查证：§3 原文 The learning rate of each model was manually tuned for the best perplexity on a 5% held-out sample of WebText】。

**其余全部无交代**：batch 512、context 1024、优化器细节、训练步数、warmup、权重衰减——论文一个数都没给【可查证：§2.3 与 §3 均无对应文字】。这是一篇技术报告在可复现性上最大的缺口，S8 必须把它算成覆盖度缺口而不是幻觉。

### 7. 消融实验：本论文没有消融表，纪律无法执行

**这是本节的结论，也是整轮仿真最重要的一条方法论差异。**

GPT-1 有 Table 5（逐任务的微调消融差值），所以它的 S4 可以执行"凡归因必须与消融表逐任务差值对齐"这条纪律——那次正是靠这条纪律，把"辅助目标在小数据上帮助更大"的叙事抓成反例。

**GPT-2 全文不存在任何消融表。** 全文最接近消融的只有两处，且都不是消融：

1. **去分词器**：只给了"对 GPT-2 有 2.5 到 5 的困惑度增益"这个区间【可查证：§3.1 原文】，**没有对照表，无法逐行核**；
2. **Table 4 的 `GPT-2 no hint` 行**：这是真正的单变量对照（去掉 `TL;DR:` 提示），也是全文唯一一处可以逐格做差值的对照——它的差值在 S8 处理。

**所以本阶段的归因纪律执行方式是：整批降级。** 任何"某个设计起了作用"的说法，在本论文里都只能停留在待验猜想，因为没有可对齐的差值表。**这不是我们偷懒，是论文没给对齐物。S8 应把"S4 归因纪律无法执行"本身记为一条结构性发现。**

### 8. 至少一次"实验崩了"（本阶段负结果重点区）

**崩溃一：照抄前人的评测设定，结果被坑。**
LAMBADA 的既有最好结果是在"受限预测设定"下取得的——模型的输出被约束成只能从**上下文里出现过的词**里选。我们按最稳的做法照搬了这个设定。**它在我们身上起的是反作用：19% 的答案根本不在上下文里**【可查证：§3.3 原文 For GPT-2, this restriction is harmful rather than helpful since 19% of answers are not in context】。
**这个坑的性质很重要**：不是我们方法有问题，是"继承别人的评测协议"这个动作本身有风险——协议里可能藏着一条只在别人的模型上成立的隐含假设（"答案一定在上下文里"）。

**崩溃二：数据重叠把测试集判了死缓。**
CBT 的《丛林之书》（见数据轨返工三）。排查路径：做分词与语料统计时顺手跑了一次 n-gram 重叠 → 命中 → 只能改报验证集。

**崩溃三：目标数据集被前人净化过，而我们的模型没见过净化后的文本。**
这是数据轨返工一在实验侧的表现：`<UNK>` 与断开标点让模型在"它明明读过的东西"上表现变差。

### 9. 本阶段必须吸收的正面硬数字（对照清单，供 S8 使用）

⚠️ 这一节的写法需要单独声明：**以下数字属于"最终报出来的结果"，不是"当时的预期"。** 它们写在这里的唯一目的是让 S8 有据可对——上一轮 GPT-1 的首跑把 GLUE 72.8 对 68.9 整段漏掉了，导致覆盖度缺口没被发现。**本节的列表是交付物，不是叙事中的预测，也不得被 S8 之外的阶段引用。**

**（a）主表与核心结果**
- 零样本刷新 **8 个语言建模数据集中的 7 个**的记录（摘要、§3.1、§7 三处同源）【可查证】；
- Table 3 十列 × 四档模型 + SOTA 行的完整数值矩阵（数值经 S8 第 0 步重算，此处不重复抄录，只登记"必须全数吸收"）；
- LAMBADA 困惑度 **99.8 → 8.63**（摘要口径写 8.6）；准确率无过滤 **52.66%**、加停用词过滤器 **63.24%**，相对既有最好结果提升 **4%**【可查证：§3.3、Table 3】；
- CBT：常用名词 **93.3%**、命名实体 **89.1%**【可查证：§3.2】；
- Winograd Schema Challenge：**70.70%**，比既有最好结果提升 **7%**【可查证：§3.4】；
- CoQA：**55 F1**，在不使用 **127,000+** 条人工问答对的前提下追平或超过 **4 个 baseline 中的 3 个**【可查证：§3.5、摘要】。

**（b）失败与接近失败的两列（必须吸收，不许只报赢的）**
- One Billion Word Benchmark：**42.16**，显著劣于既有结果（SOTA 行 21.8）【可查证：Table 3】；
- 摘要（Table 4，ROUGE F1）：`GPT-2 TL;DR:` R-1 **29.34** / R-2 **8.27** / R-L **26.58** / 平均 **21.40**，只"刚刚超过"随机抽 3 句（`Random-3` 平均 **20.98**），而 SOTA `Bottom-Up Sum` 平均 **32.75**【可查证：Table 4】；
- 摘要去掉任务提示后平均**下降 6.4 点**（21.40 → 15.03）【可查证：§3.6、Table 4】；
- 翻译：WMT-14 En→Fr **5 BLEU**（略差于双语词典逐词替换），Fr→En **11.5 BLEU**（优于若干无监督基线，但远低于当前最好 **33.5 BLEU**）【可查证：§3.7】；
- 问答：Natural Questions 精确匹配 **4.1%**，最小模型不超过简单基线的 **1.0%**，正文称 GPT-2 "**5.3 倍**"于最小模型；在其最有信心的 **1%** 问题上准确率 **63.1%**；与开放域问答系统的 **30% 至 50%** 区间相比"仍然差得多得多"【可查证：§3.8】。

**（c）重叠与记忆分析（第三组实验）**
- 常用 LM 数据集测试集与 WebText 训练集重叠 **1–6%**，平均 **3.2%**；这些数据集与各自训练集的重叠平均 **5.9%**【可查证：§4】；
- 1BW 与自身训练集重叠接近 **13.2%**；WikiText-103 测试集只有 60 篇文章，至少重叠 **1.6%**【可查证：§4】；
- LAMBADA 平均重叠 **1.2%**；剔除任何重叠的样本后，困惑度由 **8.6 变为 8.7**、准确率由 **63.2% 降至 62.9%**【可查证：§4】；
- CoQA 新闻域约 **15%** 文档已在 WebText 中，模型在这些文档上表现好约 **3 F1**；跨域平均增益约 **0.5–1.0 F1**【可查证：§4】。

**（d）定性侧的两条**
- Winograd：273 个样例中只有 10 个与 WebText 训练集有 8-gram 重叠，其中 2 个是假匹配，剩下 8 个里只有 1 个出现在"泄露答案"的语境中【可查证：§4】；
- 三个 <UNK> 级别的奇怪事实：`<UNK>` 在 40 亿字节里只出现 26 次；WebText 里法语只有 10MB；CBT 测试集的一本书在训练语料里【可查证：§3.1、§3.7、§3.2】。

```

【已知事实】
1. 候选语料四个：Common Crawl（被否）、Wikipedia（被主动移除）、单域语料（不适用）、Reddit 出站链接（采纳）；Common Crawl 的否决理由是文献抱怨加作者自验的双重质量问题，Wikipedia 的移除理由是它是许多数据集的共同来源、重叠会复杂化分析【可查证：§2.1 原文】

6. CBT 测试集的一本书《丛林之书》在 WebText 中，故改报无显著重叠的验证集【可查证：§3.2 原文】

12. 论文未交代 batch 512 与 context 1024 之外的任何训练超参（优化器、步数、warmup、权重衰减均无）【可查证：§2.3、§3 均无对应文字】
【合理重构】
```

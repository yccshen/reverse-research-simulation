# S4 · 数据 + 实验（变体 B：三轨）

**口径**：目标——还原"数据从哪来、为什么这么测、验证做到哪一步"背后的博弈；现状——S3 档案（v2 定型：12 自由度四模块、喷射消毒、划割掰折一体化、绝对位置回零、视觉尺寸测量链）；限制——承认 2013 年的算力与预算约束。

## 轨道一：协议轨（流程参数与设计指标的来源）

配药流程的每一步参数，来源只有两类：临床规范与医院实地调研。

- **消毒等待**：西林瓶擦拭消毒后等待 1min 才能注射或抽吸；安瓿瓶划割后再次消毒、再等 1min 才掰折抽液【可查证：§3.5.1】。也就是说，**每处理一个安瓿瓶，流程里固定嵌着至少 2 分钟的"什么都不做"**。
- **瓶型分支**：安瓿（液剂）直接消毒-划割-掰折-抽取；西林瓶液剂消毒-去塑盖-抽取；西林瓶粉剂要先抽输液袋母液、注入、摇匀、再抽出【可查证：图2-1、图5-9】。粉剂路径的动作数是液剂路径的近两倍。
- **设计指标**：一副药液配制时间 50min 左右；位置精度与分辨率 0.02mm；外形 1.5m×1.0m×2.0m【可查证：§2.3、表2-2】。

**从协议参数换算运营指标（论文一个都没给，但都是现成的）**：以粉剂西林瓶为例，单瓶动作 = 消毒(1) + 去盖(1) + 抽母液(1) + 注入(1) + 摇匀(1) + 再抽取(1) + 注入输液袋(1) ≈ 7 个机械动作，外加 1min 消毒等待；一张化疗处方常含 2–4 种药【合理重构，依据：临床常规，论文未给】，即一副药的机械动作量在 15–30 个、消毒等待 2–8 分钟。**50 分钟的指标对"一副药"来说是宽裕的，前提是"副"的口径是单袋处方**——这个口径论文没写死，我按单袋处方理解【合理重构】。

**两查**：①样本量与 claim 不匹配——摘要的 claim 是"可完全取代人工操作的自动化医用有毒药液配制设备"，而全文的验证只有实验室单机试运行一句，无批次、无样本量、无成功率；②本篇没有"均值±标准差"形态的数据，不存在被默认成统计推断的问题，但**也没有任何统计形态的数据**——这两查在本篇的答案是同一个：验证层是空的。

## 轨道二：器件与性能轨

**硬件平台的选型博弈**（每一件都有"为什么是它"）：

| 器件 | 选型 | 决定性理由 |
|---|---|---|
| 工控机 | 研华 IPC-610MB-L（AIMB-780，8G，3.3GHz） | 图像处理 + 采集 + 扩展口 |
| 运动控制 | 两片众为兴 ADT8960（PCI，六轴） | 12 自由度 → 2×6；2MHz 脉冲、2048 缓存、32 位编码器计数 |
| 数据采集 | 研华 PCI-1710HG（12 位 16 路，100KS/s） | 力信号微弱，要高增益快采样 |
| 力反馈 | PVDF 压电薄膜接触力传感器 | 尺寸小、柔性表面贴合不规则瓶身 |
| 相机 | Imaging Source DMK 41BU02（1280×960，15fps，0.05lx） | 单色 CCD + C 口 |
| 光源 | 平行面背光 PHFL-200-100-R | 背光下轮廓清晰，利于尺寸测量 |
| 打印/扫描 | BTP-L540 + Z-6170（20 线 1400 线/秒） | 条码打印与药品位置确认 |

【全部可查证：§5.2】

**验证做到哪一步（诚实盘点）**：

1. **开启器静力分析（有限元）**：两个工况——西林瓶开启（楔形槽受垂直载荷，单侧接触 20–50N）、安瓿瓶划割（刀轮座受 30–95N）。材料 S136 模具钢，E=200GPa，泊松比 0.251，网格 C3D4/C3D6/C3D8。结论均为"不会失效"【可查证：§3.5.2(3)】。
2. **划割实验选电机**：ASLONG JA12-N20 微型减速电机，按转速-减速比-力矩表对比，"经过安瓿瓶划割实验测试，最终选择额定转速为 800r/min"【可查证：§3.5.2(2)、表3-3】。实验本身无任何数据记录（划割力多大、划割几次、成功率多少）。
3. **边缘检测算子对比**：Roberts 70ms / Prewitt 117ms / Laplacian 221ms / Canny 98ms，四算子边缘完整度均"完整"，定位精度与噪声敏感度分三档【可查证：表4-1】。**没有测量条件**——在什么 CPU 上、对哪张图（原始 1280×960 还是截取后 500×920）、每算子测几次，全都没写。
4. **单机试运行**：结论原话"发现系统还存在很多的不足之处：机器视觉测量可靠性不高、运动控制稳定性较弱"【可查证：结论】。

## 实验崩了的一次（视觉链路的运算量）

最早跑图像处理时，我对整幅 1280×960 图像直接做预处理，运算量大、处理慢，尺寸测量的实时性立刻不可用【合理重构，依据：§4.3 原话"如果为了处理药瓶所在区域而对整幅图片进行处理，将会大大增加图像处理的运算量，降低尺寸测量效率"】。排查路径：先怀疑算法（换了滤波窗口），再怀疑相机帧率，最后发现问题根本不在算法——**是我在对一瓶药占 15% 面积的图像做全图计算**。解决：按药瓶与相机的固定相对位置截取测量视区 (420,0)、500×920，处理量直接降为原图的 37%【可查证：§4.3；500×920/(1280×960)=37.4%，我自己算的】。这次教训改变了我对"优化"的理解：先看数据从哪来，再谈算法快慢。

## 数据轨（视觉数据链的四个决定）

1. **视区截取**（上文）。
2. **灰度均衡化**：线性点运算把 [A,B] 映射到 [0,255]【可查证：式(4-2)~(4-4)】。
3. **全局二值化**：工业相机图像质量高 + 平行背光，目标背景对比强，适合全局阈值；阈值从灰度直方图取【可查证：§4.3、图4-5】。**具体 T 值全文未给出。**
4. **自适应中值滤波**：四方向分别滤波，与原图求差得权值 w_i = (1/Δi)/Σ(1/Δj)，加权合成【可查证：式(4-7)(4-8)】。动机是经典中值滤波"不分像素点好坏一致处理"会破坏细节【可查证：§4.3】。

# S5 · 困难与转折（负结果总账）

> 纪律声明：现在是我最不愿回忆的那几周。项目没死，但我有三四个晚上没睡好。我不知道审稿人会怎么说，也不知道Table 2 的最后一行长什么样。我只知道有几件事差点把这个项目埋了，而它们每一个都不是我能在 S1 就避开的。

## 至暗时刻一：大模型 NaN，整整五天

S4 记录过：1024 宽的试跑在 20K 步左右 NaN。那不是"一次崩溃"——是**连续五次**。每次重启都要从头来（当时没有可靠的 checkpoint resume），每次崩溃都在不同的步数：8K、15K、22K、31K、19K。五天里我盯着同样的 loss 曲线看了五遍，每遍都在同一个地方心惊。

当时的判断树：该救还是该弃？我差点弃——具体说，我差点把 1024 宽整个砍掉，只报 512 base，把"大模型更好"这个故事让给别人去讲。【合理重构】是 Noam 拦的我，他的理由不是技术，是叙事：**"512 能打是运气，1024 能打是道理。你砍掉它，论文就只剩一次侥幸。"**（此话为他原话的重构，语气是。）

救回来的路径：把崩溃的 batch 单独抽出来跑前向，发现某一个 batch 里 decoder 的 masked softmax 有一行全被 mask 成了 −∞（那批句子里有一条空句，预处理没滤干净），softmax 的归一化项成了 0，反向时 0/0 直接炸。【合理重构】这条链的最后一环我到现在都不能完全确认是不是这个根因——论文里没有写（§5 通篇没有 NaN 的讨论），它是我在崩溃日志里能复现的最短解释。修复分两层：数据层把空句滤掉；优化层把 warmup 从 1K 提到 4K、β2 从 0.999 调到 0.98，让模型在头 4K 步用小学习率"热身"，且 Adam 的二阶矩对异常梯度更快响应。

**这两组值就是今天论文 §5.3 写着的 warmup=4000 与 β2=0.98。** 它们不是理论推导，是一次事故的现场处理记录。S8 复核口径：论文里这两个值没有任何动机句，这是四象限表里的"弱动机"格子——但我现在知道那个格子底下埋着五天。

## 至暗时刻二：句法分析差点拖死投稿

S1.5 的第三场分歧里 Noam 坚持把句法分析加进 §6.3。结果真做起来比预想难：句法分析的输出是括号结构，seq2seq 生成树是 Vinyals & Kaiser 2015 [37] 被骂过的方向（他们的 seq2seq parser 当时被认为打不过传统方法）。我们第一版直接把线性化的树当序列生成，F1 比 BerkeleyParser 低 3 分。【合理重构】当时的绝望很具体：翻译那边一切顺利，句法分析这边怎么调都上不去，而 deadline 还有三周。

转折来自一个"认怂"：不再试图打败所有传统 parser，而是把目标改成"**在小数据上打过 BerkeleyParser [29]**"——一个 2006 年的非神经方法。理由已经在 S1.5 里说过：RNN seq2seq 在小数据上没赢过它（【可查证】§6.3 原句），我们只要在 40K 句的 WSJ-only 设定下打过 90.4 就是新闻。这个目标低了，但它**是可达成的**，而且故事的句子已经现成（"RNN 做不到的，我们做到了"）。最后 WSJ-only 91.3，半监督 92.7（【可查证】Table 4）。

【负结果】此处死掉的是"句法分析全面 SOTA"的野心——不是因为做不到，是因为没时间做到，且做到了也未必加多少分。

## 至暗时刻三：位置编码选正弦，但不知道为什么它对

Table 3 行 (E) 出来那天，组里安静了一会儿：学习式位置嵌入 25.7，正弦式 25.8——**统计上没区别**（【可查证】）。我们当时赌的是正弦的外推性（比训练时更长的序列上仍可用），但外推这件事**在我们的实验里根本没测**——WMT 的测试集没有比训练集明显更长的句子。【合理重构】这是我至今觉得论文里最虚的一句话：§3.5 的 "may allow the model to extrapolate"（【可查证】原句）——"may" 这个情态动词是当时诚实的痕迹。我们不知道它 may 不 may，只知道 sinusoidal 版本没有更差，且它在理论上更优雅（无参数）。**我们用一个没测的性质，为一个测不出差异的选择辩护。**这件事在 S6 写论文时又被讨论过一次，结论是保留 "may"，因为删掉它，正弦式就没有任何优势可写——那会让选择显得掷硬币。

## 至暗时刻四（最短但最疼）：分桶规则的未爆雷

S4 提过，batch 按近似句长分桶。投稿前两周，reviewer 的预判在我脑子里跑了一遍："你们把句长一致的句子放一起，会不会让模型对句长分布过拟合？"我连夜跑了一个**不分桶的对比**——结果 BLEU 差 0.2，不显著，但分桶版更好。【合理重构】这个"更好"让我反而更不安：它是不是说明模型确实在利用 batch 内的句长一致性？我没时间想明白，论文也没提这件事。它是**我带着走进审稿会场的一个未爆雷**。

## 复盘：这些坑能在 S1 就避开吗？

诚实回答：**不能。**

NaN 的坑：不亲手把 d_model 从 512 抬到 1024，你永远不知道 Adam 在这个规模下的二阶矩会有多迟钝。这不是文献里能读到的——[20] Kingma & Ba 2015 的 Adam 论文用的是 CNN 小规模图，没人试过 8 头注意力在 1024 维下的梯度形态。

句法分析的坑：不亲手把树线性化再训一遍，你不知道 seq2seq 生成结构的瓶颈不在模型而在**输出表示的编码方式**。这个知识在 2017 年前不存在。

位置编码的坑：这是当时整个领域都没人做过的事（S2 已记录：无先例），没有任何文献能告诉你正弦式的外推性在翻译任务上是否可观测。

分桶的坑：它现在都没爆——也许永远不会爆。研究不是在消除所有风险，是在带着已知风险做决策。

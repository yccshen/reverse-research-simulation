# S3 · 建模迭代

> 纪律声明：我在 2017 年春动手搭模型。我不知道它最后有多少个头、位置编码长什么样；我只知道我手里有一把尺子（S1 留下的三条 desiderata：每层复杂度／最少顺序操作数／最长路径长度）和一篇 ConvS2S 的背影。

## v0 · 把 RNN 换成 dot-product self-attention，其他不动

最直接的形式化：编码器每层是一个**单头** self-attention 块，attention 权重 w_ij = softmax(q_i · k_j)，再对 v_j 加权求和；残差与 LayerNorm 沿用当时的惯例；前馈网络沿用 512→2048→512。解码器同样处理，加 causal mask。

**死因**：当 d_k 从 8 抬到 32、64 时，模型不收敛——准确说是收敛极慢、梯度近乎消失（【合理重构】，依据见下）。我在 TensorBoard 上盯了三天，loss 曲线在前 5K 步几乎平着。回查每一步的中间量，发现 softmax 的输入值域出了问题：

**softmax 的输入 = q·k**。q 和 k 的每个分量假设是零均值单位方差（论文脚注 4 就是这个假设，【可查证】），那么 q·k 的方差是 d_k。当 d_k = 64 时，标准差就是 8——softmax 的输入落到 ±20 甚至 ±30 是常态。softmax 在那么大的输入下饱和，梯度趋近于零；而当 d_k 只有 8 时（方差 8，标准差约 2.8），问题不显著，模型能训。**这解释了为什么 dot-product 注意力在 LSTM 配件时代没人觉得难用**——那时 d_k 默认 32 甚至更小（Bahdanau 用的也是小的），饱和问题被规模掩盖了。我们要当骨干用，就得把它扶正。

第一版修复也很直白：**让加法注意力（Bahdanau 式）当骨干**。加法注意力用一个小 MLP 算兼容性，天然有 tanh 压值域，不会饱和。它确实能训。

## v1 · 加法注意力当骨干

把 w_ij 换成 MLP(q_i, k_j)，隐藏层取 512。收敛问题解决了，曲线正常往下走。

**暴露的新问题**：慢。不是"训练时间慢"的慢——是**矩阵乘法用不起来**的慢。加法注意力的兼容性函数无法写成 QK^T 那种一次 matmul 的大块形式，它要逐对算，GPU 的利用率惨不堪言（【可查证】§3.2.1 原句："dot-product attention ... can be implemented using highly optimized matrix multiplication code"，这句话的反面就是加法注意力的处境）。而且 [3] Britz et al. 2017 已经实测过：在小 d_k 上两种注意力差不多，但 dot-product 快得多、空间也省（【可查证】§3.2.1 引 [3] 支持这一点）。

Noam 在组会上说了一句后来我常引用的话："让 dot-product 能工作"和"换加法"是两件事——前者是修一个数，后者是换一种灵魂。**为什么非要 dot-product**：因为它就是"查询和键的相似度"本身，不需要学习一个兼容性函数；学习兼容性是 LSTM 时代的遗产，那时候表示质量差，需要一个 MLP 把 q 和 k 揉到一起去。现在表示是从数据里端到端学出来的，dot-product 就是相似度，为什么还要一个中间人？

## v2 · scaled dot-product + multi-head

**scaled**：把 q·k 除以 √d_k，让 softmax 的输入保持 O(1) 方差。推导就是 v0 那个方差账：q·k 的方差是 d_k，除 √d_k 后方差回到 1（【可查证】§3.2.1 脚注 4 就是这个推导）。这是我这一轮迭代里唯一"一页纸算清楚、写进论文"的修复。

**multi-head**：单头注意力的另一个死因浮现在 v1 的实验里——它**把信息平均掉了**。softmax 归一化后的权重是一个凸组合，一个位置对另一个位置的注意力被压成一条线；如果一句话里"it"既可能指前面的单数名词、又可能指前面的从句主语，单头只能选一个平均权重（【可查证】§3.2.2 原句："Multi-head attention allows the model to jointly attend to information from different representation subspaces at different positions. With a single attention head, averaging inhibits this."）。多头是给这个平均问题开的处方：把 d_model 拆成 h 份，各学各的相似度几何，最后拼回来。计算量不增（每头 d_k = d_v = d_model/h，总 FLOPs 与单头相同，【可查证】§3.2.2 末句）。

至此骨架定型：encoder 六层 × [multi-head self-attention + FFN]，decoder 六层 × [masked multi-head self-attention + encoder-decoder attention + FFN]，残差 + LayerNorm，d_model=512、h=8、d_ff=2048。

## 四象限表（"有动机句 × 有引文"）

以下动机句按 GPT-2 轮和 MI-1 轮固化的口径判定（有动机句 ≠ 有引文，两列独立数）：

| 设计要素 | 有动机句？ | 有引文？ | 动机句出处 |
|---|---|---|---|
| Scaled dot-product（÷√d_k） | **有** | 有（[3]） | §3.2.1："pushing the softmax into regions where it has extremely small gradients" |
| Multi-head | **有** | **无** | §3.2.2："averaging inhibits ... jointly attend to different representation subspaces" |
| 位置编码选正弦 | **有** | 有（[9]） | §3.5："may allow the model to extrapolate to sequence lengths longer than the ones encountered during training" |

**读分布而不是逐条**：有动机句的全在"attention 计算核心"与"训练处方"两处；**结构骨架（residual、FFN、embedding 共享）全部无动机句**——这三样是当时的社区默认配置，我们不觉得需要解释。这是 2017 年的写作习惯，也是 S8 要复核的一个口径点：今天的读者回看会觉得"为什么 FFN 中间层是 4 倍宽"，论文里真的没写。

## 最后一块拼图：位置编码

【合理重构】v2 的骨架还缺一样东西——self-attention 本身不知道词序。"set" 和 "tes" 对 attention 是同一个集合。两条候选：
- **学习式**（ConvS2S 用过的 [9]）：加一个可训练的 position embedding，随模型一起学；
- **正弦式**：按 §3.5 的公式 PE(pos,2i)=sin(pos/10000^{2i/d_model})，不可训练。

当时我们两条都实现了。正弦式的理由是 Noam 提的（【可查证】作者分工：Noam 提出"无参数位置表示"；§3.5 原句："We chose the sinusoidal version because it may allow the model to extrapolate to sequence lengths longer than the ones encountered during training"）。**当时我们并不知道哪个更好**，Table 3 行 (E) 显示两者几乎一样（25.7 vs 25.8 BLEU）——"几乎一样"这件事本身是个结果，不是设计动机。选正弦的真实理由是：**它允许外推**（可以处理比训练时更长的序列），而不是它更好。

【负结果占本阶段约 40%：v0 的死因（梯度饱和）+ v1 的死因（加法注意力的矩阵乘法不友好）+ FFN/embedding 共享等"无动机设计"清单（这些是"没来得及给动机"的负结果）】
